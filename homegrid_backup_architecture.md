# Архитектура и схемы разработки HomeGrid Backup

Документ описывает внутреннее устройство **HomeGrid Backup**, связи между модулями, потоки данных, синхронизацию фоновых задач с интерфейсом и конвейер сборки.

---

## 1. Архитектурная схема зависимостей (Слои и модули)

Архитектура построена по принципу **однонаправленных зависимостей сверху вниз**: интерфейсы зависят от ядра, ядро — от бизнес-логики, бизнес-логика — от базового слоя. Циклические импорты исключены.

## 2. Схема конвейера резервного копирования (`core/backup.py`)

Каждая операция бэкапа проходит через **6 строго изолированных этапов** в фоновом потоке `run_backup_task()`:

    [Старт: GUI / Tray / CLI / Cron]
                   │
                   ▼
    ┌─────────────────────────────────────────────────────────────────┐
    │ ЭТАП 1. ПОДГОТОВКА И ВЕРИФИКАЦИЯ ХОСТА (0% -> 10%)              │
    │ • Нормализация URL (normalize_server_url)                       │
    │ • Если адрес пуст -> автопоиск в LAN (scan_lan_servers)         │
    │ • Двухэтапная проверка подлинности сервера HGM (если нет '!')   │
    └──────────────┬──────────────────────────────────────────────────┘
                   │
                   ▼
    ┌─────────────────────────────────────────────────────────────────┐
    │ ЭТАП 2. АВТОРИЗАЦИЯ И РАЗБЛОКИРОВКА ЭКСПОРТА (10% -> 20%)       │
    │ • Проверка активной сессии (/api/auth/status)                   │
    │ • При необходимости запрос LOGIN PIN через engine.ask_modal()   │
    │ • Запрос EDITOR PIN для прав на создание архива                 │
    └──────────────┬──────────────────────────────────────────────────┘
                   │
                   ▼
    ┌─────────────────────────────────────────────────────────────────┐
    │ ЭТАП 3. ЗАПУСК И ОЖИДАНИЕ СБОРКИ НА СЕРВЕРЕ (20% -> 75%)        │
    │ • POST /api/export/start -> получение job_id                    │
    │ • Опрос статуса каждые 2.5 с:                                   │
    │   preparing -> copying -> packing -> checking -> ready          │
    │ • При сбросе задачи сервером -> автоматический перезапуск       │
    └──────────────┬──────────────────────────────────────────────────┘
                   │
                   ▼
    ┌─────────────────────────────────────────────────────────────────┐
    │ ЭТАП 4. ПОТОКОВОЕ СКАЧИВАНИЕ ZIP (75% -> 90%)                   │
    │ • Скачивание во временный файл .part (буфер 1 МБ)               │
    │ • Расчёт мгновенной и средней скорости (МБ/с)                   │
    │ • При обрыве сети -> до 7 автоповторов с паузой                 │
    └──────────────┬──────────────────────────────────────────────────┘
                   │
                   ▼
    ┌─────────────────────────────────────────────────────────────────┐
    │ ЭТАП 5. ПРОВЕРКА ЦЕЛОСТНОСТИ И СОХРАНЕНИЕ (90% -> 96%)          │
    │ • Потоковый проход по ZIP (буфер 1 МБ):                         │
    │   1) Проверка CRC32 каждого файла внутри архива                 │
    │   2) Расчёт SHA-256 всего архива и сверка с X-Checksum-Sha256   │
    │ • Атомарное переименование .part -> YYYY-MM-DD_Weekday_HH-MM.zip│
    │ • Запись файла контрольной суммы <имя_архива>.zip.sha256        │
    └──────────────┬──────────────────────────────────────────────────┘
                   │
                   ▼
    ┌─────────────────────────────────────────────────────────────────┐
    │ ЭТАП 6. MIRROR, РОТАЦИЯ И ОТЧЁТ (96% -> 100%)                   │
    │ • Если включён Mirror -> копирование .zip и .sha256 во 2 папку  │
    │ • Кольцевая ротация GFS (core/gfs.py): удаление копий > N       │
    │   (архивы с тегом KEEP не трогаются, остальные -> в Корзину)    │
    │ • Запись в op_history, системное уведомление ОС и окно отчёта   │
    └─────────────────────────────────────────────────────────────────┘

## 3. Межпоточная синхронизация UI и фоновых задач

Поскольку `Tkinter` не потокобезопасен, фоновые потоки (`backup.py`, `network.py`) **никогда не обращаются к виджетам напрямую**. Вместо этого используется двусторонний механизм через `BackupEngine`:

       ФОНОВЫЙ ПОТОК (Worker)                   ОБЪЕКТ ENGINE                  ГЛАВНЫЙ ПОТОК (Tkinter)
    ────────────────────────────             ───────────────────             ────────────────────────────
    1. Вызывает engine.log(...)   ─────────► Кладёт в log_queue ◄────────── 2. _poll_ui() каждые 300 мс
       и engine.set_progress()               и обновляет pct/stage              читает очередь и обновляет
                                                                                ProgressBar, Log и Tray

    3. Нужен PIN / Отчёт:
       res = engine.ask_modal(    ─────────► Сохраняет modal_data
         "pin", "Enter PIN", ...             и сбрасывает Event
       )
       [Поток ждёт modal_event]                                  ◄────────── 4. _poll_ui() видит modal_data
                                                                                и открывает _EmbeddedDialog
                                                                                (Linux) или Toplevel (Win)

                                                                             5. Пользователь вводит PIN
                                             Сохраняет modal_res  ◄──────────    и нажимает «Подтвердить»
    6. Просыпается и получает     ◄───────── и ставит Event.set()               -> engine.submit_modal(pin)
       введённый PIN в res

> **Режим без GUI (`--cli` / `--silent`):** метод `engine.ask_modal()` определяет отсутствие активного окна Tkinter и автоматически переключается на консольный ввод (`getpass` / `input`) или безопасное значение по умолчанию без блокировки выполнения.

## 5. Сводная таблица модулей

| Слой | Модуль | Зависит от | Кем вызывается | Ответственность |
| :--- | :--- | :--- | :--- | :--- |
| **Entry** | `main.py` | `config`, `engine`, `backup`, `scheduler`, `terminal`, `window`, `tray`, `android_app` | Запуск ОС | Mutex / `flock`, CLI-флаги, маршрутизация режимов. |
| **Core** | `core/engine.py` | `config`, `i18n`, `terminal` | Все модули | Состояние `state`, очередь логов, кэш статистики, `Event`-мост. |
| **Core** | `core/backup.py` | `config`, `files`, `network`, `gfs`, `i18n` | `main`, `window`, `tray`, `network`, `android` | Авторизация, экспорт, скачивание, CRC32 + SHA-256, Mirror, уведомления. |
| **Core** | `core/network.py` | `config`, `backup` (лениво) | `backup`, `window`, `android` | HTTP + CookieJar, Ping, TCP, верификация HGM, сканер LAN. |
| **Core** | `core/gfs.py` | `files` | `backup`, `dialogs` | Кольцевая ротация последних N копий, тег `KEEP`, очистка. |
| **Core** | `core/scheduler.py` | `config` | `main`, `dialogs` | `schtasks` (Win/WSL), `crontab` + autostart (Linux), `LaunchAgent` (macOS). |
| **Base** | `core/config.py` | stdlib + `keyring` | Все модули | Детект ОС, `config.json`, `keyring` / `.env`, ротация `backup.log`. |
| **Base** | `core/files.py` | `i18n` | `backup`, `gfs`, `window`, `dialogs`, `tray` | Корзина, нативные диалоги папок, детерминированные даты `format_backup_dt`. |
| **Base** | `core/i18n.py` | stdlib | `engine`, `files`, `window`, `dialogs`, `tray`, `widgets` | Локализация `EN / UK`, перевод виджетов, очистка эмодзи на Linux. |
| **GUI** | `gui/window.py` | `config`, `files`, `network`, `backup`, `styles`, `widgets`, `tray`, `dialogs`, `i18n` | `main.py` | Главное окно `HomeGridApp`, цикл `_poll_ui()`, управление Mirror. |
| **GUI** | `gui/dialogs.py` | `config`, `files`, `gfs`, `backup`, `scheduler`, `styles`, `tray`, `i18n` | `window.py` | `_EmbeddedDialog` / `Toplevel`: Настройки, Статистика, Анализ, Журнал, Отчёт. |
| **GUI** | `gui/tray.py` | `config`, `files`, `backup`, `i18n` | `main`, `window`, `dialogs` | Системный трей `pystray` с прогрессом и слушателем повторного запуска. |
| **GUI** | `gui/widgets.py` | `styles`, `i18n` | `window.py` | Кастомный `StyledProgressBar` (градиент `v8` и текстовый `LITE`). |
| **GUI** | `gui/styles.py` | `config`, `i18n` | `window`, `dialogs`, `widgets` | Темы `dark`/`light`, расчёт DPI и `_NET_WORKAREA`, `ToolTip`. |
| **CLI** | `console/terminal.py` | `config` | `main`, `engine` | Цифровой индикатор прогресса и логов в терминале (`--cli`, `--silent`). |
| **Mobile** | `mobile/android_app.py` | `config`, `network`, `backup` | `main.py` | Интерфейс Kivy для Android. |
