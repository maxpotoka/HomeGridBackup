# Правила генерации автопатчей для HomeGrid Backup (Windows PowerShell)

## 1. Формат запуска и защита от зависаний в PowerShell
* **Только `here-string` + `python`:** каждый блок патча оформляется строго как `@' ... '@ | python` без многострочных фрагментов кода в пояснениях.
* **Запрет на `input()`:** при передаче скрипта через `| python` поток `stdin` занят кодом скрипта — вызов `input()` вызывает `EOFError` или зависание. Скрипт завершается через `print(..., flush=True)`.
* **Автопереход в корень проекта:** скрипт проверяет наличие `gui/window.py`; при поиске через `os.walk` обязательно исключаются каталоги `('.git', '.venv', 'venv', 'build', 'dist', '__pycache__', '.patch_bak')`.
* **Короткие порции:** крупные правки делятся на блоки по 20–30 строк с пошаговым выводом `[1/N] OK`.

## 2. Кодировка символов и защита от искажений при переносе
* **Запрет на кириллицу и спецсимволы в якорях (`old_s`):** при вставке через буфер обмена Windows PowerShell кириллица и символы (`•`, `—`, `✔`) искажаются. Поиск мест вставки выполняется только по чисто ASCII-якорям или регулярным выражениям (`re.search` по ASCII-именам функций и переменных).
* **Строгое экранирование `\uXXXX`:** весь добавляемый не-ASCII текст (украинский, русский, иконки, стрелки, тире) записывается исключительно через `\uXXXX` или `\U000XXXXX`.
* **Строгий UTF-8 и LF (`\n`):** файлы читаются с `encoding="utf-8"` и записываются с `newline="\n"`.

## 3. Совместимость с Python 3.8–3.11 (сборка Nuitka в GitHub Actions)
* **Запрет на обратный слэш `\` внутри `{...}` в f-строках:** конструкции вида `f"{'\u041c\u0411'}"` вызывают `SyntaxError` на Python 3.8–3.11. Любые условные строки с `\uXXXX` или кавычками сначала выносятся в отдельную переменную (`_lbl = ...`), и только потом подставляются в `f"{_lbl}"`.
* **Запрет на `def` / `class` после `;`:** при правке минифицированного однострочного кода новые определения функций, циклов и блоков `try` всегда начинаются с новой строки с точным табулированным отступом (`\n\t\t...`).

## 4. Порядок операций, проверка якорей и версионирование
* **Сначала замены, потом вставка в начало файла:** все замены по смещениям `t[:m.start()] + ... + t[m.end():]` выполняются до добавления `# patch-id:` или `import` в начало файла, чтобы не сдвигать индексы.
* **Самопроверка по якорям до записи на диск:** каждая замена проверяется на уникальность (`count == 1` или точное совпадение `re.search`) и верифицируется через `assert new_s in t` в памяти. При несовпадении запись на диск отменяется.
* **Резервное копирование и компиляция:** перед перезаписью оригинал сохраняется в `.patch_bak/` (папка добавлена в `.gitignore`), после записи выполняется `py_compile.compile(fp, doraise=True)`.
* **Обновление версий:** при изменении модулей обновляется шапка версии файла (`+0.01`), а в `core/config.py` — глобальные `SCRIPT_VER` и `BUILD_DATE`.
